# unibrow

A native iOS SMB file browser. Browse shares on your network, view images and videos, and manage saved connections — with security considered at each layer.

## Security overview

unibrow is designed as a **local-first** file browser. All file access goes directly between your iPhone and your SMB server. There is no cloud backend, analytics SDK, or third-party file relay.

```
┌─────────────┐     SMB (optional SMB3 encryption)     ┌─────────────┐
│   unibrow   │ ◄────────────────────────────────────► │  Your NAS   │
│   (iOS)     │                                        │  / server   │
└─────────────┘                                        └─────────────┘
       │
       ▼
 Local only: Keychain · encrypted thumbnail cache · temp video files
```

## Network security

### Direct SMB connection

- File listings, thumbnails, images, and videos are fetched over **SMB2/3** using [AMSMB2](https://github.com/amosavian/AMSMB2) (libsmb2).
- The app talks **only** to servers you configure. No other network endpoints are used for file access.

### Optional SMB3 encryption

Each saved connection has a **Use SMB3 Encryption** toggle.

When enabled, the app calls `connectShare(encrypted: true)`, which requests **SMB3 sealing** (payload encryption on the wire). If the server does not support it, the connection fails rather than silently falling back to unencrypted SMB3 data transfer.

When disabled, SMB traffic on your LAN is not encrypted at the SMB layer (credentials still use SMB authentication mechanisms).

**Recommendation:** Enable SMB3 encryption for connections over untrusted networks. On a trusted home LAN, leaving it off is a common tradeoff for compatibility.

## Credential storage

### Passwords → Keychain

SMB passwords are stored in the iOS **Keychain**, not in plaintext in app preferences.

- Saved on **Test Connection** and **Save Connection**
- Loaded when connecting to a saved share
- Keyed by `host|share|username`

Connection metadata (name, host, share, username, encryption preference) is stored in **UserDefaults**. New saves write an empty string for the password field in that JSON blob — the real secret lives only in Keychain.

### What you should know

- Passwords use Keychain accessibility **`WhenUnlocked`** (available while the device is unlocked).
- Deleting a connection from the list does **not** currently remove its Keychain password entry (orphaned credentials may remain until overwritten by a new connection with the same host/share/username).

## Thumbnail cache

Thumbnails are downsampled to **200px** max and cached on disk to avoid re-downloading from SMB.

### Encryption at rest

Disk cache files are **not plain JPEGs**. Each cached thumbnail is:

1. Downsampled to a small JPEG in memory
2. Encrypted with **AES-256-GCM** (CryptoKit)
3. Written as an opaque `.thumb` file under `Library/Caches/SMBThumbnailCache/`

### The encryption key

On **first use**, the app:

1. Generates a random 256-bit AES key (CryptoKit `SymmetricKey`)
2. Stores it in the Keychain under a dedicated service ID
3. Reuses that key for all subsequent cache reads/writes on that install

The key is:

- **Generated by the app** — not hardcoded, not derived from your SMB password
- **Per install** — `WhenUnlockedThisDeviceOnly`, not synced via iCloud Keychain
- **Automatic** — users never see or manage it

Clearing the thumbnail cache in Settings deletes cached files but keeps the same key (new thumbnails re-encrypt with it).

### File protection

The thumbnail cache directory uses iOS **Data Protection** class **`.complete`**: files are inaccessible when the device is locked.

### In memory

While browsing, decrypted thumbnails also live in an in-memory `NSCache` for performance. This is expected for any image UI and is only present while the app is running.

## Temporary video files

Video playback requires a **local file** for `AVPlayer`. When you open a video:

1. The full file is downloaded from SMB to `tmp/SMBTempVideos/`
2. File protection **`.completeUnlessOpen`** is applied after download
3. The file is **deleted** when you close the player or leave the view
4. Leftover temp files from crashes are **swept on app launch**

This is the **most sensitive on-disk exposure** in the app: a full video exists locally until playback ends. Thumbnails and images do not persist full originals to disk in the same way.

---

## Full-size images

Opening an image in the gallery downloads the **entire file into memory** (`Data` → `UIImage`). No persistent temp file is written for images.

- **Disk:** No full-size copy left behind after you close the gallery
- **Memory:** Full resolution is held in RAM while viewing (and may remain briefly until released)

## Other local data

| Data | Location | Protection |
|------|----------|------------|
| Saved connections (no password) | UserDefaults | Standard app sandbox |
| SMB passwords | Keychain | `WhenUnlocked` |
| Thumbnail cache key | Keychain | `WhenUnlockedThisDeviceOnly` |
| Thumbnail blobs | Caches | AES-GCM + `.complete` |
| Temp videos (during playback) | tmp | `.completeUnlessOpen`, deleted on close |
| Hide hidden files preference | UserDefaults | Non-sensitive |

## iOS sandbox

Like all App Store apps, unibrow runs in a **sandbox**. Other apps cannot read its Caches, tmp, or Keychain items on a non-jailbroken device. Thumbnail encryption adds **defense in depth** — cache files are ciphertext even if someone extracts the app container while the device is unlocked.

## Threat model

### What this app is good at

- Keeping SMB passwords out of UserDefaults (for current saves)
- Encrypting thumbnail cache on disk with a per-install Keychain key
- Optional SMB3 encryption for network transport
- No third-party servers or telemetry for file access
- Cleaning up temp videos after playback

### What it does not protect against

- **Device unlocked + app in use** — decrypted thumbnails, full images in RAM, and temp videos are accessible to the running app
- **Jailbroken or compromised devices** — sandbox and encryption assumptions weaken
- **Shoulder surfing** — no app-level PIN beyond the device passcode
- **Server-side access** — anyone with access to the SMB share sees the same files
- **SMB encryption off** — LAN traffic may be readable on the network segment
